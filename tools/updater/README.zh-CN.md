# QtScrcpy 0.4.3-rc.1 保留脚本覆盖更新器

这是 Windows x64 的离线覆盖更新工具，不是另一个投屏程序。它内置本次已构建的完整 0.4.3-rc.1 程序包；原始包 SHA-256 为 `ed4a5b091485b9d3a8f7871e983e1d0a2dfdb44141866fd46edea82230278d04`。本次仅改变交付和更新方式，应用功能版本不变。

## 使用

1. 在旧 QtScrcpy 中保存需要保留的录制、退出程序。仅留在内存中且未保存的录制无法保留。
2. 把更新包完整解压到旧程序目录以外，例如下载目录。不要将它直接解压覆盖旧目录。
3. 运行 `QtScrcpyUpdate.exe`，点击“选择旧程序”，选择你目前实际使用的那个 `QtScrcpy.exe`。
4. 勾选已保存录制、退出旧版，然后点击“备份并覆盖更新”。核对显示的原目录后确认。
5. 成功后仍从原来的快捷方式或原目录启动 QtScrcpy。脚本和程序目录没有搬迁，通常不需要重新导入脚本。

仅接受本地 NTFS 磁盘上的 0.4.0—0.4.3 系列 x64 程序，拒绝 32 位、不能识别的版本和可识别的较新版本。需要 .NET Framework 4.8。保留并与 EXE 放在一起的 `.config` 文件是更新器自身运行配置，不会复制进旧程序目录。

更新器不联网、不上传脚本、不修改注册表、不请求自动提权，也不会自动启动新版。工具没有数字签名，请核对下载来源和 SHA-256，不要无条件忽略系统安全提示。

## 哪些内容保留

现有 `config/`（包括 `config.ini`、`userdata.ini`）、`keymap/`、宏文件（如 `*.qsmacro.json`）、自建脚本目录及其它不在本次程序包替换清单内的文件不覆盖、不清理。即使旧键位文件与新版示例同名，也不会替换；新版的 config/keymap 默认文件完全不安装。

已有 `qt.conf` 和 `sndcpy.bat` 保留原文件，仅在原目录没有这些文件时补充。程序 EXE、DLL、投屏服务、运行资源、发行说明和构建信息按内置包的实际文件清单更新；内容相同的文件跳过。不会按照“删除整个旧目录再复制”的方式更新，也不会删除原目录里的未知文件。

AppData 下的应用绑定、应用名称缓存、方向恢复备份，以及你保存到其它磁盘或目录的脚本、由 `QTSCRCPY_CONFIG_PATH` / `QTSCRCPY_KEYMAP_PATH` 指向的数据，更新器均不修改，不调整其路径。**这些外部位置不属于本工具的目录备份范围**；重要脚本仍应另存一份独立备份。

## 自动备份与校验

实际覆盖前先完整复制旧程序目录中的所有普通文件（包括其中的脚本），并逐文件核对 SHA-256。备份位于旧目录旁，例如：

```text
D:\Tools\QtScrcpy\                         原位置继续使用
D:\Tools\QtScrcpy.qsc-update-backups\
    20260917-xxxxxx-xxxxxxxx\
        old-install\                        更新前的程序及目录内文件
        old-files.xml                       更新前文件校验清单
        transaction.xml                     程序文件恢复记录
        stage\                             已校验的暂存运行文件
```

备份包含脚本正文，可能有敏感内容；请与原脚本同样妥善保管，不要公开上传。备份不会自动删除。需要“旧目录大小 + 约 350 MiB”的额外可用空间；还需对旧目录和其父目录具备写入权限。极长路径、符号链接或目录联接会拒绝更新，而不是冒险沿链接修改外部数据。

更新结束时再次核对所有没有替换的旧文件内容与更新前一致。需要替换的文件被占用、只读或不可写时停止，不会强杀进程。若提示 adb.exe 被占用，请正常结束相关 ADB 会话后重试；内容与新版一致的 adb.exe 不需要替换。

## 失败回退与中断恢复

普通替换错误会尝试自动恢复已替换的程序文件；如果锁定、权限或磁盘错误导致恢复也失败，会明确说明“恢复未完成”，保留备份供恢复，不会假装成功。

断电或强制结束可能留下部分新旧混合程序。不要直接启动，重新运行更新器，点击“恢复备份 / 中断恢复”，选择对应备份目录中的 `transaction.xml`。检测到未完成事务时，工具会阻止再次覆盖，要求先恢复。整个目录不是一次性原子事务；持久化恢复记录用于处理这类中断。

手动回退也只恢复本次替换的程序文件，**不会将更新后新录制、修改的脚本或配置退回旧数据**。对于该次更新新增的运行文件，只有内容仍与当时一致才会删除；后来出现的用户文件不清理。恢复前先验证所有备份与当前程序文件；备份损坏、程序后来被其他更新修改、或备份被搬走时拒绝盲目恢复。请勿改动 `transaction.xml`。

这不等同于已经读取或验收你的真实脚本。主程序仍为 0.4.3-rc.1 候选版，手机适配边界沿用上一版；更新器不改变宏格式或应用配置格式。
