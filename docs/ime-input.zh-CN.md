# 实体键盘与中文拼音（0.4.10-rc.1）

## 原因与本次范围

UHID 相当于把实体键盘接到手机：按键由手机输入法处理。Windows 拼音和手机拼音是两个独立的输入法，中/英状态不会自动同步。旧投屏窗口只有实体键码转发，没有接收 Windows 拼音选词结果的通道；游戏映射占用 Shift 或空格时，相关按键也不会再作为手机输入法快捷键。

本版保留原有 UHID 与游戏映射行为，在右侧工具栏增加 **“输入法”**：提供绕过映射的手机输入法切换按钮，以及真正接收电脑输入法组合文字的原生 Qt 输入框。不是将 Windows 输入法直接映射成 HID，也不是在投屏上增加隐形的全局键盘捕获。

## 用手机拼音

1. 在手机上启用带中文拼音的输入法，进入目标应用并点击文本框。
2. 保持 QtScrcpy 的 UHID 实体键盘开启，电脑切到英文输入状态。
3. 点击右侧 **输入法**，根据手机输入法的快捷键设置选择 **手机中/英（Shift）**、**手机切换（Ctrl+空格）** 或 **手机切换（Shift+空格）**。
4. 关闭输入法窗口或点击投屏，继续输入拼音并在手机候选栏选词。

这些按钮直接向当前同一个 UHID 键盘发送完整的按下/松开序列，不执行游戏映射，也不会新建第二台键盘。不是所有手机输入法都使用相同快捷键；按钮只报告“按键请求已发送”，不声称手机已经切换为中文。需要时可点击“手机输入法设置”或“手机实体键盘设置”，由你在手机上选择；程序不安装输入法、不修改默认输入法，也不自动扩大权限。

如果字母本身已经绑定为游戏操作，应先切到普通输入模式再打字。专用按钮绕过映射，并不意味着把所有游戏按键同时变成文字。

## 用 Windows 拼音选词后发送中文

1. 先点击手机里要输入文字的文本框。
2. 点击 QtScrcpy 右侧 **输入法**，在窗口内的文字框切换为 Windows 中文拼音并输入。
3. 在电脑候选栏完成选词后，点击 **发送已选文字**。

拼音组合过程、候选字和普通按键留在电脑文字框内，不同时传给手机。只有明确点击发送，才把已选定的文字通过现有的手机剪贴板粘贴协议发送一次。Enter 只换行，不自动发送；还在组词时发送按钮不可用。请求成功提交后清空文字框，失败则保留文字，不自动重试。

这是一条单独的中文输入通道，不是在投屏画面内直接显示 Windows 候选框；它不替代 UHID 的游戏和原生键盘用途。文字可包含中文、换行和 emoji，单次最多 64 KiB UTF-8，不截断发送。

**会替换手机剪贴板。** 本功能不主动读取或改写电脑剪贴板，但既有剪贴板同步设置可能使两端随后同步。目标应用可能不允许粘贴，设备返回写入成功也不是应用已经插入文字的回执；请在手机确认。不要在密码、付款、验证码等敏感页面试用。不会自动按手机的“发送”或“提交”键。

## 输入保护与兼容

- 只作用于打开窗口时的手机会话，不向群控设备广播文字或输入法切换键。
- 录制、回放、暂停中的回放或等待绑定应用期间不允许发送；请先停止操作。避免把手动文字混入脚本或目标页面。
- 断开手机后禁用发送，未发送的草稿留在窗口中供复制，不会发往相同地址的新连接。关闭窗口后不持久保存草稿，也不打印文字内容到日志。
- 普通 UHID 输入、已绑定游戏按键、8× 宏、应用标签、设备旋转、60 Hz 手机箭头、音频和 ScrcpyKeyMapper 版本保持原有行为。

## 验证边界

回归测试使用真实生产控制器、Qt 输入法事件和可控通信，检查组词/提交隔离、一次性 Unicode 粘贴、修饰键释放、映射共存、长度边界及宏/断线保护。自动测试不等于已经在用户的 Windows 拼音配置、实体手机输入法和具体应用上验收。

参考：scrcpy 官方 keyboard.md 与 Issue #4722；Qt QInputMethodEvent 文档。本修复不承诺所有 Android 输入法都有同一种中/英切换键。
