# 手机光标性能验证（0.4.9）

2026-09-26，在 V1824A / Android 11、1080×2340、60 Hz 屏幕上通过 Wi-Fi ADB 测试。
QtScrcpy 投屏连接保持运行。基准使用生产 `PhoneCursor` 调度器，以合成的连续鼠标位置驱动同一 Android 辅助程序，不注入点击。

| 项目 | 结果 |
|---|---:|
| 旧版按 30 Hz 请求，实际确认更新率 | 29.70 次/秒 |
| 旧版逐条等确认、取消发送间隔后的吞吐率 | 54.58 次/秒 |
| 新版目标调度率 | 60 Hz |
| 新版实际发送率（20 秒，剔除前 30 条） | 59.77 次/秒 |
| 新版手机绘制提交率 | 59.62 次/秒 |
| 新版指令往返延迟：平均 / 中位 / P95 | 17.11 / 15.30 / 32.56 毫秒 |
| 手机收到命令至提交事务：平均 | 2.17 毫秒 |
| 发送至手机提交绘制：估计平均 / P95 | 9.54 / 17.78 毫秒 |

通过手机单调时钟接收/提交时间与电脑发送/确认时间求共同可行的时钟偏差范围；
单向延迟使用范围中点估算，时钟对齐不确定度约 ±2.60 毫秒。往返延迟不需要跨设备对时。

另加一路 Android 10 秒录屏时，手机绘制提交率为 59.05 次/秒，录屏文件为 49.58 帧/秒。
**绘制提交率不是屏幕实际可见更新率**：录屏含合成和额外编码负载，其帧率也不能直接证明手机物理面板每秒显示了多少次新光标。
手机报告的面板上限为 60 Hz；软件目标已提高到 60 Hz，Wi-Fi 抖动或较重负载仍会降低实际更新率。

确认是在 `SurfaceControl.Transaction.apply()` 返回后发出，表示提交了事务，并非像素已经发光。
完整的物理鼠标到手机屏幕延迟还包括最多一帧左右的电脑采样等待，以及手机合成、扫描和面板响应；
精确测量需要高速摄影或光电传感器。本测试没有测得“9.54 毫秒的物理显示延迟”。
