# 设备旋转（0.4.2-rc.1）

本版从 0.4.1-rc.1 的应用名称、`>` 隐藏标签及宏运行中标签切换版本继续开发；未回退到旧的 0.4.0 主分支。音频、8×、宏格式、UHID 和双击补丁不变。

## 四个选项

点击投屏右侧的圆形箭头“设备旋转”，展开菜单：

- **切换横竖屏**：根据手机主屏当前方向请求另一轴的方向，保留原自动旋转模式及应用方向策略。应用或重力感应可能立即恢复方向；这时明确报告“请求已执行但未保持”，不声称已经横屏。
- **固定横屏**：关闭自动旋转，并启用系统固定到用户方向的策略，尝试让桌面也按横屏布局。方向根据系统报告的横屏角度选取，兼容自然方向是横屏的平板，不一律写死 90 度。
- **固定竖屏**：同理固定为系统报告的竖屏方向。
- **恢复原设置**：恢复第一次通过此菜单修改前的自动旋转、用户方向及固定策略；不是任意写回“自动旋转开启”或“默认竖屏”。连续选择横屏/竖屏不覆盖第一次备份。

命令只作用于 **手机主显示屏 display 0**，不是电脑图像旋转。摄像头/动态虚拟显示会话不提供此菜单；其他高级显示模式也不要把它当作虚拟屏方向控制。主窗口“锁定视频方向”是另一项采集参数，不会被本功能自动修改。

原 Ctrl+R 在工具栏初始化后复用“切换横竖屏”流程；UHID 模式仍可能把此组合键交给手机，建议直接点击菜单。

## 操作宏与提示

正在录制、执行或暂停的宏仍拥有输入。点击旋转时会询问是否先停止宏/录制及自动返回任务；取消不会改变手机。不会绕过保护在旧坐标脚本仍执行时强制旋转。停止录制不等于自动保存，请保留并保存需要的录制。

确认后按顺序读取状态、备份、执行、重新读取验证。不需要 root，不修改分辨率/DPI、音频、手机权限或系统文件。命令失败或系统拒绝目标方向会报告错误，并在设备/用户仍一致且没有新宏时尝试回滚到本次操作前的状态。

## 备份和退出

备份在当前 Windows 用户的 QtScrcpy 配置目录 `rotation-backups`，按 **手机物理序列号 + Android 用户 ID** 的摘要区分。可跨同一手机的 USB/Wi-Fi 地址及程序重启恢复。不覆盖损坏备份；读不到可靠身份/状态、目录不可写或另一窗口正在操作时，不修改手机。

**退出程序、关闭投屏或断线不会保证自动恢复手机方向。** 固定设置可能仍生效，请在退出前手动选择“恢复原设置”。断线时取消未完成的 ADB 客户端请求，保留恢复文件；已到达手机的命令不能撤销。重新连回同一手机、同一 Android 用户后可以手动恢复。不要删掉备份目录。

Android 11 的标准 `wm set-fix-to-user-rotation` 不提供原始三态策略查询，`dumpsys` 只输出生效布尔值。此情况下会在修改前明确提示：自动旋转和角度按记录恢复，固定策略只恢复原有生效行为，不能区分原先是 `default` 还是显式 `disabled`。提供 `wm fixed-to-user-rotation` 查询的新系统按原始策略值恢复。没有假装在旧系统上实现逐标记无损恢复。

## 兼容性边界

通过 `wm help` 检测 Android 旧/新命令名，读取主显示屏状态后才写入。ROM 不提供必需命令、拒绝授权或改变输出格式时，明确报错而不是猜测。某些厂家桌面即使系统方向已改变也可能使用兼容布局、黑边或排版不佳；固定方向不能保证任意应用都具有良好的横屏界面。锁屏不被绕过。

本版为候选版，自动化测试使用 Qt 菜单和模拟的系统响应；你的 V1824A Android 11 仍需实际验证。建议停止宏后，先在桌面测试固定横屏，再恢复原设置。
