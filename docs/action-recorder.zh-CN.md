# 操作宏 0.1.0-rc.1（首个真机试用候选版）

本功能记录 QtScrcpy 已转换好的 Android 控制消息，而不是屏幕视频。普通键鼠操作和游戏映射生成的触摸动作按录制时的含义保存。实体手机兼容性、游戏表现和实际延迟仍需使用者验收；自动化测试不能代替真机测试。

## 开始使用

1. 将完整 Windows x64 压缩包解压到一个新目录，不要只复制 `QtScrcpy.exe`，也不要覆盖正在使用的旧版目录。
2. 手机开启 USB 调试，通过数据线连接并在手机上授权。在 QtScrcpy 中核对序列号并选择实体手机，避免误选 MuMu 等模拟器。
3. 打开投屏，等待画面出现。点击右侧工具栏的播放圆圈图标，进入 `Action Macro 0.1.0-rc.1`。
4. 先在计算器、便笺或测试应用中点击 `Start recording`，在电脑投屏窗口完成点击、长按、滑动或键盘操作。直接用手触摸手机的动作不会由此录制。
5. 点击 `Stop recording`，再点击 `Save...` 保存 `*.qsmacro.json`。停止录制会补齐仍处于按下状态的按键/触点释放动作；保存也会保留最后一个动作到停止录制之间的等待时间。
6. 把手机恢复到相同的起始页面，先设置重复次数 `1` 并点击 `Play`。通过单次测试后再尝试 `3` 次等有限循环。
7. 重复次数 `0` 表示持续循环，并有额外确认；循环间隔单位为毫秒，范围 `0–600000`。每轮还会保留录制开始到首个动作的等待，以及录制末尾的等待，所以循环间隔不是整个周期长度。

## 停止和恢复

- `Emergency stop` 停止当前设备。`Ctrl+Shift+X` 停止本进程已打开宏窗口所登记的设备。
- Windows 会尝试注册系统全局快捷键。窗口底部会显示注册是否成功；成功时即使另一个程序处于前台也可触发。若被其他软件占用或注册失败，明确退回 QtScrcpy 应用内快捷键，不应假定它仍然全局有效。
- 关闭宏窗口或按 Escape 时先停止，再提示保存未保存的录制；在提示中点 Cancel 也不会自动恢复回放。
- 停止时清除客户端待发输入，并重置映射器的延迟操作。结束后游戏映射可能处于关闭状态，需要按该映射的开关键重新开启。这是为了避免按住的方向键或延迟连点在停止后继续生成触摸。
- 播放时暂停普通键鼠控制输入，避免人工操作和宏互相干扰。先停止宏，再手动调整手机页面。
- 设备断连不会自动继续旧任务。旧宏窗口绑定原设备会话，不能自动控制一个重连的新会话；重连后重新打开投屏及宏窗口，并加载之前保存的文件。
- 控制发送失败会停止宏。运行中的显示尺寸或方向变化也会停止宏；开始回放时尺寸不一致会拒绝执行。
- 事件落后于计划时间超过 2 秒时停止，而不是集中补发过期点击。这可降低电脑休眠、长时间卡顿后误操作的风险，但不是硬实时保证。

释放消息是客户端对正常连接的补发尝试，不是手机端执行确认。拔线、系统卡死或应用失去响应时，不能保证消息到达或生效。不要在支付、删除、账号管理等高风险页面做验收，也不要依赖无限循环进行无人值守操作。

## JSON 格式与边界

格式名 `QtScrcpyActionMacro`，版本 `1`。本版新增可选 `durationMs`，兼容旧版没有该字段的宏。每个事件包含相对时间 `atMs` 和语义化消息字段，不直接保存私有二进制协议。

加载时检查格式、精确版本号、字段类型、非负整数时间、时间顺序、最长时长、坐标边界、屏幕元数据、消息类型和文本长度；损坏文件不会覆盖内存中的已有宏。限制为 100,000 个事件、24 小时、64 MiB。录制提前预留释放事件空间，界面和文件采用同一限制。

事件坐标是录制时的绝对设备画面坐标。尺寸相同不代表页面内容相同；不同应用布局、裁剪起点、虚拟显示区域和系统缩放也可能导致位置错误，应重新录制。此版本没有图像识别、页面等待条件、坐标自适应、步骤编辑或多设备同步调度。

文字和剪贴板内容可能以明文保存在 JSON 中。不要录入密码、验证码或隐私资料；不要把含敏感内容的宏上传到公开仓库。只加载自己检查过的宏，不要在重要应用中执行来源不明的脚本。

## 构建与测试

主仓库的 `QtScrcpy/QtScrcpyCore` 子模块固定到对应核心提交；克隆时使用 `--recurse-submodules`。推荐使用本分支的 `Action Macro RC` 工作流构建 Windows x64 包。

核心独立测试：

```sh
cmake -S QtScrcpy/QtScrcpyCore/tests -B build-macro-tests
cmake --build build-macro-tests --config RelWithDebInfo
ctest --test-dir build-macro-tests -C RelWithDebInfo --output-on-failure
```

该测试入口分别注册 28 个用例；主项目完整构建中核心测试是一个包含相同 28 个用例的 CTest 程序，另有 5 项控制器/界面集成测试。Linux 工作流另外使用 AddressSanitizer 和 UndefinedBehaviorSanitizer 检查内存与未定义行为。以对应提交的 CI 实际结果为准，不把测试数量当作已通过声明。

Windows 包包含 `build-info.json`（主项目及核心提交、构建编号、真机未验收标志）和 SHA-256 校验值。编译、自动化测试及启动检查成功只表示可以进入实体手机验收，不表示已在全部 Android 版本、机型或应用上验证。

## 实体手机验收记录

记录手机型号、Android 版本、连接方式、显示尺寸/方向、测试应用、主/core 提交号，以及下面各项的通过/失败和日志：

- 点击、长按、滑动、滚轮、普通键盘与游戏映射分别录制、保存、重启程序加载、单次回放。
- 三次有限循环，检查次数、每轮间隔和末尾等待。
- 长按/拖动/持续按键中紧急停止，检查没有继续点击或残留按下状态。
- 宏窗口、投屏窗口及其他程序前台分别验证停止快捷键。
- 关闭窗口、拔线、重连、横竖屏切换后没有旧任务自动恢复。

发现异常时停止宏，保留日志和无隐私的复现脚本；不要用反复无限循环代替定位问题。
