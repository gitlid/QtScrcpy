# QtScrcpy 0.4.5-rc.1 — 保持投屏横/竖屏展示

在 0.4.4 的任务标签、逐行 ×、方向控制和保留脚本更新器上继续。本次不改变手机方向策略、音频、宏格式、键位文件、应用绑定或核心子模块。

## 解决重复旋转和窗口反复横竖切换

旧版记住的是固定的电脑端旋转角度，例如 +90°。手机进入游戏时自身从 1080×2340 变为 2340×1080，旧角度仍被叠加，显示又变成竖向；退出游戏时窗口再变一次。

这版记住的是“保持横屏/竖屏展示”的目标。手机自己切换方向时，根据当前真实视频帧计算有效旋转，不会累加：

- 先在竖屏桌面顺时针转 90°：电脑端显示横向，并自动保持横屏。
- 进入本身横屏的游戏：电脑端补偿角度改为 0°，不再把游戏转第二次。
- 返回竖屏桌面：重新采用原来的 90°；用逆时针选定横屏则返回原来的 270°。
- 以上自动切换不调整电脑端窗口的位置、大小，也不退出全屏或最大化。手机分辨率/导航栏改变造成比例不同，画面在原窗口内等比适配，可能留黑边，不拉伸和裁掉内容。

## 操作入口

右侧旋转按钮 → **仅旋转投屏画面（不改变手机）**：

- **保持横屏展示（自动适配）**：游戏已经横屏时也可以直接选，保持当前窗口。
- **保持竖屏展示（自动适配）**：同样适配另一轴。
- **跟随手机方向（取消保持）**，或“恢复画面方向”：取消电脑端锁定与旋转，恢复跟随手机。
- 原有顺时针 90°、逆时针 90°、180°仍可使用；手动旋转后自动保持选定的展示轴。明确选择 180°会保留相应的翻转意图。

不要把此项与上层“固定横屏/固定竖屏”混淆：上层修改的是手机方向；本项只处理电脑画面，不执行手机 wm/settings，不重新排版竖屏应用。先前已修改的手机固定方向不会被本项偷偷恢复，需要时仍使用上层“恢复原设置”。

展示偏好保留于本次投屏会话，切应用不重置；重新连接默认跟随手机，没有写入、覆盖用户脚本或配置。

## 坐标与宏

画面和鼠标点击/拖拽/双击/滚轮使用同一有效旋转。手机原始尺寸仍传递给控制器和宏，已有宏不改写成电脑画面坐标。

手机真实旋转依然可能触发原有宏的尺寸保护、暂停及应用恢复；保持电脑窗口并不意味着旧坐标宏可以无条件在另一套手机尺寸中继续执行。手动改变展示设置仍沿用停止宏/录制的确认（默认取消），未保存录制不会自动保存。自动视频帧适配不反复调用这类确认或重置宏。

该功能沿用普通 OpenGL 投屏路径；不提供给 Metal 和动态虚拟显示。当前帧宽高能判断横/竖轴，但不据此声称能识别同轴的手机物理 180°旋转；编码器已经处理的画面朝向仍以收到的视频为准。

## 更新与验证边界

使用本版保留脚本覆盖更新器，保存录制、退出旧版，更新器解压在旧目录外，然后选择正在使用的旧 QtScrcpy.exe。config、keymap、宏、应用配置、方向备份不重置。备份、校验与恢复机制不变；目录外的数据不修改，但不在旧目录备份中。

新增回归包括用户日志中的 1080×2340 / 2340×1080 往返、逆时针、重复回调不累计旋转、显式取消、半周旋转、输入变换、实际 VideoForm 普通/最大化/全屏窗口及真实 OpenGL 画面验证。构建与通过数量以实际 CI 记录为准；没有连接用户手机或读取用户真实脚本，仍需真机确认。
